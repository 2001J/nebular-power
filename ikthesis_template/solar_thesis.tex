\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
This thesis presents the design and implementation of a Solar Energy Monitoring and Control System targeted at residential and small commercial installations offered on financing plans. The system addresses payment compliance monitoring, real-time energy visibility, tamper detection, and remote operational control. The backend is implemented with Spring Boot 3 (Java 21) and exposes REST APIs and STOMP/SockJS for real-time updates; the frontend is built with Next.js and React, and a Raspberry~Pi simulation framework produces realistic telemetry and events for development and testing. We document the system architecture (high- and low-level design), database schema derived from JPA entities, module structure and key methods, implementation decisions (security, data representation, real-time communication), test plans and lessons learned, and practical deployment guidance. The documentation strictly reflects the implemented codebase to ensure reproducibility and evaluation clarity.

\chapter{Raspberry Pi Simulation Framework}

\section{Overview}
The simulation framework generates realistic solar installation data for testing and demonstration purposes. It simulates energy production, device heartbeats, tamper events, and responds to remote commands as if it were an actual Raspberry Pi installation in the field.

The simulator serves several purposes:
\begin{itemize}
    \item Provides test data without requiring actual solar hardware
    \item Demonstrates system features including real-time monitoring, tamper detection, and remote service control
    \item Enables testing of edge cases and error conditions
\end{itemize}

\section{Core Components}
The simulation framework consists of five main Python modules in the \texttt{pi\_simulation/} directory:

\subsection{main.py}
The main coordinator script that:
\begin{itemize}
    \item Loads configuration from \texttt{config.json} (or generates \texttt{default\_config.json} if not present)
    \item Initializes and runs all simulator components in separate threads
    \item Provides interactive console for manual tamper event triggering (p=physical, v=voltage, c=connection, l=location)
    \item Handles command-line arguments for overriding configuration
    \item Manages graceful shutdown on Ctrl+C
\end{itemize}

\subsection{energy\_simulator.py}
Generates realistic energy production and consumption data:
\begin{itemize}
    \item Simulates daily solar generation with peak at midday using time-based calculations
    \item Optional weather effects that randomly reduce production
    \item Variable consumption patterns throughout the day
    \item Sends energy readings to backend at configurable intervals (default: 15 seconds)
\end{itemize}

\subsection{heartbeat\_simulator.py}
Emulates device status updates:
\begin{itemize}
    \item Sends periodic heartbeat messages with device health information
    \item Simulates battery levels with realistic discharge/charge patterns
    \item Reports diagnostic data (temperature, memory, uptime, signal strength)
    \item Configurable reporting interval (default: 45 seconds)
\end{itemize}

\subsection{tamper\_simulator.py}
Generates security tamper events:
\begin{itemize}
    \item \textbf{Physical Tamper}: Simulates unauthorized physical access
    \item \textbf{Voltage Tamper}: Unusual voltage patterns indicating bypassing attempts
    \item \textbf{Connection Tamper}: Unauthorized disconnection of monitoring equipment
    \item \textbf{Location Tamper}: Device appears to have been moved
    \item Random event generation based on configurable probabilities
    \item Manual triggering via interactive console or command-line flag
\end{itemize}

\subsection{command\_handler.py}
Listens for and processes server commands:
\begin{itemize}
    \item Polls backend API for pending commands at regular intervals (default: 15 seconds)
    \item Simulates execution of commands (suspend/activate service, reboot device, update firmware)
    \item Maintains service state in \texttt{service\_state\_[ID].json}
    \item Sends command responses with success/failure status
\end{itemize}

\subsection{auth\_helper.py}
Manages authentication with the backend:
\begin{itemize}
    \item Authenticates using JWT tokens via configured credentials
    \item Automatically includes authentication headers in API requests
    \item Handles token refresh if needed
\end{itemize}

\section{Configuration}
The simulator is configured via \texttt{config.json} with the following structure:

\textbf{general}: Installation ID, server URL (e.g., \texttt{http://localhost:8080}), authentication credentials

\textbf{energy}: Enable/disable, base/peak generation watts, consumption range, update interval, weather simulation toggle

\textbf{heartbeat}: Enable/disable, interval, device ID, diagnostics and battery simulation toggles

\textbf{tamper}: Enable/disable, random event generation, interval range, probabilities for each tamper type

\textbf{command}: Enable/disable, polling interval, simulated success rate

\section{Usage}
\textbf{Setup:}
\begin{verbatim}
cd pi_simulation
python3 -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
\end{verbatim}

\textbf{Configuration:} Edit \texttt{config.json} to set:
\begin{itemize}
    \item \texttt{installation\_id}: Must match an installation in the backend database
    \item \texttt{server\_url}: Backend API URL (localhost for same machine, IP address for remote)
    \item \texttt{auth.username} and \texttt{auth.password}: Valid customer credentials
\end{itemize}

\textbf{Run:}
\begin{verbatim}
python3 main.py
\end{verbatim}

\textbf{Interactive Commands:}
\begin{itemize}
    \item \texttt{p} - Trigger physical tamper event
    \item \texttt{v} - Trigger voltage tamper event
    \item \texttt{c} - Trigger connection tamper event
    \item \texttt{l} - Trigger location tamper event
    \item \texttt{q} - Quit simulation
    \item Ctrl+C - Stop simulation
\end{itemize}

\textbf{Command-line Options:}
\begin{verbatim}
python3 main.py -c custom_config.json  # Use custom config
python3 main.py -u http://192.168.1.10:8080  # Override server URL
python3 main.py -i 5  # Override installation ID
python3 main.py -t physical  # Trigger tamper event and exit
\end{verbatim}

\section{Dependencies}
The simulator requires Python 3.8+ and the following packages (in \texttt{requirements.txt}):
\begin{itemize}
    \item \texttt{requests} - HTTP communication with backend API
    \item \texttt{urllib3} - Robust HTTP connection handling
    \item \texttt{python-dateutil} - Date/time manipulation
    \item \texttt{python-dotenv} - Environment variable management
    \item \texttt{colorama} - Console output formatting
    \item \texttt{loguru} - Advanced logging
\end{itemize}

\section{Data Flow}
The simulator communicates with the backend using HTTP:
\begin{itemize}
    \item POST to \texttt{/api/energy/readings} - Send energy production/consumption data
    \item POST to \texttt{/api/heartbeat} - Send device status updates
    \item POST to \texttt{/api/tamper/events} - Report tamper events
    \item GET from \texttt{/api/commands/pending} - Poll for commands
    \item POST to \texttt{/api/commands/\{id\}/response} - Send command execution results
    \item POST to \texttt{/api/auth/login} - Authenticate and obtain JWT token
\end{itemize}

All requests (except auth) include JWT authentication headers obtained during initialization.

\section{Limitations}
\begin{itemize}
    \item Commands like reboot and firmware update are simulated (logged but not executed) to avoid disrupting the simulator
    \item Energy production follows simple time-based algorithms, not actual solar physics
    \item Service suspension updates internal state but doesn't physically disable hardware
    \item Suitable for demonstration and testing, not production monitoring
\end{itemize}
