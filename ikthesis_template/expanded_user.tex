\section{System Overview}
\label{sec:system-overview}

\subsection{What is the Solar Energy Monitoring and Control System?}
\label{subsec:system-description}

The Solar Energy Monitoring and Control System is a comprehensive platform designed for solar energy monitoring and payment compliance in developing markets. It enables real-time monitoring of solar installations and automated payment tracking for Pay-As-You-Go (PAYG) solar financing models.

\textbf{Key Capabilities:}
\begin{itemize}
    \item \textbf{Energy Monitoring}: Real-time tracking of solar energy production and consumption
    \item \textbf{Payment Management}: Automated tracking of customer payments and loan compliance
    \item \textbf{Security Monitoring}: Detection and alerting of potential tampering or unauthorized access
    \item \textbf{Multi-Role Access}: Role-based access control for administrators and customers
    \item \textbf{Comprehensive Reporting}: Analytics and insights for operational decision-making
\end{itemize}

\subsection{Who Should Use This Documentation}
\label{subsec:target-audience}

\textbf{Primary Users:}
\begin{description}
    \item[System Administrators] Technical staff responsible for platform configuration, user management, and system maintenance
    \item[Solar Installation Customers] End-users with solar installations who monitor their energy production and manage payments
\end{description}

\textbf{Secondary Users:}
\begin{description}
    \item[Technical Support Staff] Personnel providing customer support and troubleshooting
    \item[Research Personnel] Academic researchers and developers evaluating the system
    \item[Financial Officers] Staff responsible for payment processing and loan management
\end{description}

\textbf{Prerequisites:}
\begin{itemize}
    \item \textbf{Administrators}: Basic web application management skills, user management understanding
    \item \textbf{Customers}: Basic computer literacy, web browser usage, email access
    \item \textbf{Support Staff}: Customer service experience, basic troubleshooting skills
\end{itemize}

\subsection{System Components}
\label{subsec:system-components}

\textbf{User-Facing Components:}
\begin{itemize}
    \item \textbf{Web Dashboard}: Responsive web application for monitoring and management
    \item \textbf{Device Simulation}: Raspberry Pi-based framework for testing and demonstration
    \item \textbf{Notification System}: Email and web-based alerts and notifications
\end{itemize}

The system implements role-based access control with clearly defined permissions for different user types, as detailed in Table~\ref{tab:role-privileges}.

\subsection{System Requirements}

\subsubsection{Browser Compatibility}
The Solar Energy Monitoring System is designed to work with modern web browsers. Below are the supported browsers and their minimum version requirements:

\begin{itemize}
    \item \textbf{Web Browsers}:
    \begin{itemize}
        \item Chrome version 90 or newer
        \item Firefox version 88 or newer
        \item Edge version 90 or newer (Chromium-based)
        \item Safari version 14 or newer (macOS/iOS)
        \item Opera version 74 or newer
    \end{itemize}
    \item \textbf{Browser Configuration}:
    \begin{itemize}
        \item JavaScript enabled (required for all functionality)
        \item Cookies enabled (required for authentication and user preferences)
        \item Local Storage enabled (required for session management)
        \item Pop-up blockers configured to allow notifications from the platform
    \end{itemize}
    \item \textbf{Network Requirements}:
    \begin{itemize}
        \item Minimum 1 Mbps download speed for basic functionality
        \item Recommended 5 Mbps for optimal performance with real-time updates
        \item Stable connection for continuous monitoring features
        \item HTTPS support (all traffic is encrypted)
    \end{itemize}
    \item \textbf{Display Requirements}:
    \begin{itemize}
        \item Minimum screen resolution: 1280 $\times$ 768 pixels
        \item Recommended resolution: 1920 $\times$ 1080 pixels or higher
        \item Support for responsive design (adapts to various screen sizes)
        \item Color depth: 16-bit minimum, 24-bit recommended
    \end{itemize}
\end{itemize}

\subsubsection{Hardware Simulation Environment}
The current research implementation includes a Raspberry Pi simulation framework:

\begin{itemize}
    \item \textbf{Raspberry Pi}: Raspberry Pi 4 Model B with 4GB RAM (recommended) or Raspberry Pi 3B+ minimum
    \item \textbf{Storage}: MicroSD card 32GB Class 10 or higher
    \item \textbf{Power Supply}: Official Raspberry Pi power supply (5V 3A for Pi 4, 5V 2.5A for Pi 3)
    \item \textbf{Network Connectivity}: Wi-Fi 802.11n or Gigabit Ethernet for reliable communication
    \item \textbf{Operating System}: Raspberry Pi OS (32-bit or 64-bit) or Ubuntu 20.04 LTS for Pi
    \item \textbf{Python Environment}: Python 3.8+ with the following packages:
    \begin{itemize}
        \item requests (for HTTP communication)
        \item numpy (for data simulation)
        \item schedule (for periodic tasks)
        \item paho-mqtt (for IoT communication protocols)
    \end{itemize}
\end{itemize}

\subsubsection{Network and Security Requirements}

\begin{itemize}
    \item \textbf{Firewall Configuration}: 
    \begin{itemize}
        \item Port 443 (HTTPS) open for web access
        \item Port 80 (HTTP) for automatic HTTPS redirects
        \item Port 5432 (PostgreSQL) accessible only from application servers
        \item Port 22 (SSH) for administrative access with key-based authentication
    \end{itemize}
    \item \textbf{SSL/TLS}: TLS 1.2 minimum, TLS 1.3 recommended
    \item \textbf{Security Protocols}:
    \begin{itemize}
        \item Strong password policies enforced
        \item Session timeout configuration (configurable, default 30 minutes)
        \item CORS (Cross-Origin Resource Sharing) properly configured
        \item Content Security Policy (CSP) headers implemented
    \end{itemize}
\end{itemize}

\section{Installation and Setup Guide}
\label{sec:installation-setup}

This section provides installation procedures for deploying the Solar Energy Monitoring and Control System using Docker (recommended) and a local development setup.

\subsection{Prerequisites}
\label{subsec:prerequisites}

Before installation, ensure you have:

\begin{itemize}
    \item \textbf{Docker}: Docker Desktop 4.0+ or Docker Engine 20.10+
    \item \textbf{Docker Compose}: Version 2.0+ (included with Docker Desktop)
    \item \textbf{System Resources}: 4GB RAM minimum, 8GB recommended
    \item \textbf{Network Access}: Internet connection for downloading images
    \item \textbf{Ports Available}: 3000 (frontend), 8080 (backend), 5432 (database)
\end{itemize}

\subsection{Quick Docker Installation}
\label{subsec:docker-installation}

\subsubsection{Step 1: Get the Source Code}
\begin{enumerate}
    \item Clone the repository:
    \begin{verbatim}
git clone https://github.com/2001J/nebular-power.git
cd nebular-power
    \end{verbatim}
    \item Verify Docker is running:
    \begin{verbatim}
docker --version
docker-compose --version
    \end{verbatim}
\end{enumerate}

\subsubsection{Step 2: Launch the System}
\begin{enumerate}
    \item Start all services with Docker Compose:
    \begin{verbatim}
docker-compose up -d
    \end{verbatim}
    \item Wait for services to initialize (approximately 2-3 minutes)
    \item Verify all containers are running:
    \begin{verbatim}
docker-compose ps
    \end{verbatim}
\end{enumerate}

\subsubsection{Step 3: Access the Application}
\begin{enumerate}
    \item Open web browser and navigate to: \url{http://localhost:3000}
    \item Default administrator credentials:
    \begin{itemize}
        \item Email: \texttt{admin@solar.com}
        \item Password: \texttt{admin123}
    \end{itemize}
    \item Change default password on first login
\end{enumerate}

\subsection{System Configuration}
\label{subsec:system-configuration}

\subsubsection{Environment Variables}
The system can be configured through environment variables in the \texttt{compose.yaml} file:

\begin{verbatim}
POSTGRES_DB=nebula_power
POSTGRES_USER=nebulapower
POSTGRES_PASSWORD=secure_password
JWT_SECRET=your-jwt-secret-key
FRONTEND_URL=http://localhost:3000
BACKEND_URL=http://localhost:8080
\end{verbatim}

\subsubsection{Production Deployment}
For production deployment, modify the \texttt{compose.yaml} file:

\begin{enumerate}
    \item Update environment variables with secure values
    \item Configure SSL certificates for HTTPS
    \item Set production database credentials
    \item Update CORS settings for your domain
    \item Configure backup and monitoring
\end{enumerate}

\subsection{Device Simulation Setup}
\label{subsec:device-simulation}

\subsubsection{Raspberry Pi Simulation (Optional)}
For hardware simulation demonstration:

\begin{enumerate}
    \item Set up Raspberry Pi with Python 3.8+
    \item Install simulation dependencies:
    \begin{verbatim}
pip3 install -r pi_simulation/requirements.txt
    \end{verbatim}
    \item Configure backend connection in \texttt{pi\_simulation/config.json}
    \item Run simulation:
    \begin{verbatim}
cd pi_simulation
python3 main.py
    \end{verbatim}
\end{enumerate}

\subsection{Local Development (Alternative to Docker)}
For local testing without containers:
\begin{enumerate}
  \item \textbf{Backend (Spring Boot)}: from repo root run \texttt{./mvnw spring-boot:run}. API docs: \url{http://localhost:8080/swagger-ui/index.html}
  \item \textbf{Frontend (Next.js)}: \texttt{cd solar\_frontend \&\& pnpm install \&\& pnpm dev}. Open \url{http://localhost:3000}
  \item \textbf{Simulator (optional)}: \texttt{cd pi\_simulation \&\& pip install -r requirements.txt \&\& python main.py -u http://localhost:8080}
\end{enumerate}

\subsection{Verification and Testing}
\label{subsec:verification}

\subsubsection{System Health Check}
Verify installation success:

\begin{enumerate}
    \item Check all containers are healthy:
    \begin{verbatim}
docker-compose logs
    \end{verbatim}
    \item Test web interface at \url{http://localhost:3000}
    \item Log in with administrator credentials
    \item Create a test customer account
    \item Verify energy monitoring dashboard displays
\end{enumerate}

\subsubsection{Common Issues and Solutions}

\begin{description}
    \item[Port Conflicts]
    \begin{itemize}
        \item Ensure ports 3000, 8080, and 5432 are not in use
        \item Modify port mappings in \texttt{compose.yaml} if needed
        \item Stop conflicting services or use different ports
    \end{itemize}
    
    \item[Container Startup Failures]
    \begin{itemize}
        \item Check Docker service is running
        \item Verify sufficient system resources (RAM, disk space)
        \item Review container logs: \texttt{docker-compose logs [service-name]}
        \item Restart services: \texttt{docker-compose restart}
    \end{itemize}
    
    \item[Database Connection Issues]
    \begin{itemize}
        \item Wait for database initialization (may take 2-3 minutes)
        \item Check database container logs: \texttt{docker-compose logs postgres}
        \item Verify environment variables are correctly set
        \item Restart backend service: \texttt{docker-compose restart backend}
    \end{itemize}
\end{description}

\subsection{System Management}
\label{subsec:system-management}

\subsubsection{Starting and Stopping}
\begin{itemize}
    \item \textbf{Start system}: \texttt{docker-compose up -d}
    \item \textbf{Stop system}: \texttt{docker-compose down}
    \item \textbf{Restart service}: \texttt{docker-compose restart [service-name]}
    \item \textbf{View logs}: \texttt{docker-compose logs -f}
\end{itemize}

\subsubsection{Data Management}
\begin{itemize}
    \item \textbf{Backup database}: Docker volumes persist data automatically
    \item \textbf{Reset system}: \texttt{docker-compose down -v} (removes all data)
    \item \textbf{Update images}: \texttt{docker-compose pull \&\& docker-compose up -d}
\end{itemize}

\subsection{Account Setup and Access}
\label{subsec:account-setup}

\subsubsection{Customer Onboarding Process}
In this research implementation, the account provisioning follows a controlled approach where customers are onboarded to the Solar Energy Monitoring and Control System platform by administrators once their solar energy system is installed. Self-registration is not available for customers, ensuring systematic data collection for the research study. The onboarding process follows these steps:

\begin{enumerate}
    \item Administrator navigates to Customer Management in the admin dashboard and selects "All Customers"
    \item Administrator clicks the "Add Customer" button
    \item Administrator enters customer information:
    \begin{itemize}
        \item Full name
        \item Email address (will be used as username)
        \item Phone number
        \item Temporary password (with confirmation)
    \end{itemize}
    \item System sends an account activation email to the customer's email address
    \item Customer clicks the activation link and sets their own password (minimum 8 characters, including uppercase, lowercase, number, and special character)
\end{enumerate}

The customer onboarding interface is shown in Figure~\ref{fig:customer-onboarding}, which displays the administrator's view of the onboarding process.

\textit{Note: Terms of service, privacy policy acceptance, and multi-factor authentication are planned for future versions of the platform but are not implemented in the current version.}

\subsubsection{Login Procedure}
Registered users can access the system through:

\begin{enumerate}
    \item Navigate to the login page at \url{https://nebula-power.com/login} (this URL is an example; replace with your deployment URL)
    \item Enter email address and password
    \item Click the "Sign In" button

Users can manage their passwords through the following functions:

\section{Security and Troubleshooting Instructions}
\label{sec:security-troubleshooting}

This section provides comprehensive guidance on security best practices, common issues, and troubleshooting procedures for the Solar Energy Monitoring and Control System.

\subsection{Security Best Practices}
\label{subsec:security-practices}

\subsubsection{Password Security}

\textbf{Password Requirements:}
\begin{itemize}
    \item Minimum 8 characters in length
    \item Must contain at least one uppercase letter (A-Z)
    \item Must contain at least one lowercase letter (a-z)
    \item Must contain at least one number (0-9)
    \item Must contain at least one special character (!@\#\$\%\textasciicircum\&*)
    \item Cannot be the same as the previous 5 passwords
    \item Cannot contain common dictionary words or personal information
\end{itemize}

\textbf{Password Management Guidelines:}
\begin{itemize}
    \item Change passwords every 90 days (configurable by administrator)
    \item Never share passwords with other users
    \item Use different passwords for different systems
    \item Consider using a reputable password manager
    \item Report suspected password compromise immediately
\end{itemize}

\subsubsection{Session Security}

\textbf{Session Management:}
\begin{itemize}
    \item Always log out when finished using the system
    \item Do not leave unattended sessions open
    \item Sessions automatically expire after 30 minutes of inactivity
    \item Avoid using shared or public computers for sensitive operations
    \item Clear browser cache and cookies after use on shared computers
\end{itemize}

\textbf{Browser Security:}
\begin{itemize}
    \item Ensure browser is updated to the latest version
    \item Enable automatic security updates
    \item Disable password saving for the NebulaPower platform
    \item Use private/incognito browsing mode on shared computers
    \item Verify HTTPS connection (look for lock icon in address bar)
\end{itemize}

\subsubsection{Data Protection}

\textbf{Information Handling:}
\begin{itemize}
    \item Do not share login credentials with unauthorized persons
    \item Report any suspected security incidents immediately
    \item Verify recipient before sharing sensitive installation data
    \item Use secure communication channels for sensitive discussions
    \item Regularly review account activity for unusual patterns
\end{itemize}
